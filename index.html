Dataset — songs.csv

Data 80 songs × 10 columns — what each column means
Column Type Range Description ────────────────────────────────────────────────────────── title string — song name artist string — artist name genre string — 38 unique genres mood string — label: happy/sad/energetic/calm/ romantic/focused/angry/nostalgic energy float 0–1 0 = very quiet, 1 = very intense valence float 0–1 0 = sad/negative, 1 = happy/positive tempo float BPM speed (e.g. 120 = medium, 180 = fast) danceability float 0–1 suitability for dancing acousticness float 0–1 0 = electric/synth, 1 = fully acoustic popularity int 0–100 streaming count proxy

The 6 numeric columns (energy → popularity) are the features the ML model learns from. The mood column is the label it predicts. To improve accuracy, add more rows to songs.csv in the same format — or connect to the Spotify API which provides these exact values for any track.

ML models (classifier.py)

ML Decision Tree — winner at 68.75% test accuracy
Strategy: learns a series of if/else rules on feature values. Example rule learned: IF valence > 0.70 AND energy > 0.60 → predict: happy IF acousticness > 0.75 AND valence < 0.30 → predict: sad IF energy > 0.88 AND valence < 0.45 → predict: angry Pros: fast, explainable, human-readable rules. Cons: can overfit (memorise training data).

The tree splits features at thresholds that best separate moods. Each split maximises "information gain" — how much knowing the answer reduces uncertainty about the mood label.

ML K-Nearest Neighbors — 56.25% test accuracy
Strategy: find the 3 most similar songs in feature space and vote. Example: Your song has energy=0.8, valence=0.9 → Find 3 nearest songs in 6D space → 2 are "happy", 1 is "energetic" → Prediction: happy (majority vote) Pros: intuitive, no training phase. Cons: slow on large datasets, sensitive to feature scale.

KNN doesn't actually "learn" anything — it just memorises the dataset and compares new songs to existing ones at prediction time using Euclidean distance in feature space.

ML Random Forest — 100% train / 50% test (overfit)
Strategy: 100 decision trees trained on random data subsets, then vote. Why it overfit here: - Only 80 songs (10 per mood) - 100 trees memorised tiny training splits - Not enough data to generalise Fix: add more songs to songs.csv. With 500+ songs, Random Forest usually wins. Pros: handles noise, resistant to overfitting on larger datasets. Cons: slow to train, less explainable.

The 100% train / 50% test gap is a classic overfitting signal. The ensemble memorised the 70 training songs perfectly but failed to generalise. More data always helps Random Forest the most.

ML Naive Bayes — 62.50% test accuracy
Strategy: uses probability theory — P(mood | features). Uses Bayes' theorem: P(happy | energy=0.8, valence=0.9) ∝ P(energy=0.8 | happy) × P(valence=0.9 | happy) × P(happy) "Naive" = assumes features are independent of each other. In reality, energy and danceability are correlated — but the approximation still works reasonably well. Pros: very fast, works well with small datasets. Cons: independence assumption is rarely true.

Despite its simplifying assumption, Naive Bayes often outperforms more complex models on small datasets — which is why it achieved the best cross-validation score (63.75%) even though Decision Tree won on the test set.

How the recommender works

Core Cosine similarity — step by step
Step 1: Each mood has a pre-defined "ideal" audio profile (6D vector) happy → [0.80, 0.90, 0.65, 0.85, 0.10, 0.85] calm → [0.12, 0.55, 0.25, 0.20, 0.90, 0.75] angry → [0.95, 0.28, 0.75, 0.68, 0.03, 0.85] energy valence tempo dance acoustic pop Step 2: All 80 songs are represented as scaled 6D vectors. Step 3: Cosine similarity = cos(θ) between two vectors similarity = (A · B) / (|A| × |B|) Result: 0 = completely different direction 1 = identical direction = perfect match Step 4: All songs ranked by similarity → top N returned. Why cosine (not Euclidean distance)? Cosine ignores magnitude — a soft happy song and a loud happy song both point in the "happy direction" and both score high. Euclidean would penalise the soft one.

This is content-based filtering — each song is matched based on its own audio properties rather than "users who liked X also liked Y". It works even with no user rating history, making it perfect for a beginner project.

Output charts (auto-generated)

Chart 1 model_comparison.png — which model is best?
Grouped bar chart: 4 models × 3 metrics Train accuracy → how well it learned training data Test accuracy → performance on unseen songs (most important) CV mean → 5-fold cross-validation average (most reliable) Big gap between Train & Test = overfitting Random Forest: 100% train vs 50% test = severely overfit Decision Tree: 91% train vs 69% test = mild overfit, acceptable

Cross-validation (CV) is more reliable than a single test split because it averages 5 different train/test splits. A model with high CV mean and low CV std is the most trustworthy for real-world use.

Chart 2 mood_clusters.png — visualising 6D data in 2D
Scatter plot using PCA (Principal Component Analysis) PCA compresses 6 audio features → 2 axes: PC1 (≈42% variance) = mainly energy + danceability PC2 (≈28% variance) = mainly valence + acousticness Each dot = one song, colored by mood. What tight clusters mean: mood is easy to classify What overlapping clusters mean: moods share similar audio (energetic + angry often overlap — both high energy, low valence)

PCA finds the directions in 6D space where songs vary the most, then projects everything onto 2 axes you can plot. Well-separated clusters in this 2D view usually predict good classification accuracy.

Chart 3 confusion_matrix.png — where the model makes mistakes
8×8 heatmap: rows = actual mood, columns = predicted mood Reading it: Diagonal cells (top-left to bottom-right) = correct predictions Off-diagonal = mistakes Example: Row "angry", Col "energetic" = 1 → 1 angry song was incorrectly predicted as energetic (makes sense: both have high energy) Row "romantic", Col "romantic" = 2 → both romantic test songs predicted correctly ✓

The most common mix-ups reveal which moods are musically similar in the feature space. Angry and energetic frequently confuse classifiers because they share high energy and fast tempo — only valence truly separates them.

Feature importance is measured by how much each split on that feature reduces impurity (Gini index) across all 5 tree levels. Features used near the top of the tree affect more samples, so they tend to score higher.
